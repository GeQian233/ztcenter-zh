# 开发文档（内部）

> 这是项目的技术实现说明，面向开发者。面向使用者的介绍见根目录 [README.md](../README.md)。

基于**官方 ZeroTier One 服务**的 Windows 图形客户端。不修改、不替换官方二进制，通过官方本地 JSON 接口（`127.0.0.1:9993`）管理节点与网络，在其上补充了中文界面、网络标签、根节点（planet）与 MOON 管理、后台驻留能力。

**已提供合并安装包**：一个安装程序同时装好官方内核与控制台，无需分别安装。

## 2. 安装

### 2.1 一键安装包（推荐）

运行 `dist\ZTCenter-Setup-1.11.0.exe`，按向导完成即可，**无需先装官方客户端**。控制台 exe 已嵌入 `requireAdministrator` 清单，双击即请求管理员权限（UAC 一次），不再弹出程序内的权限提示框。安装程序会：

1. 安装官方 **ZeroTier One 1.16.2** 内核（Windows 服务 + 虚拟网卡驱动）；若已安装同版本或更高版本则自动跳过。
2. 复制控制台到 `C:\Program Files\ZTCenter\`。
3. 创建开始菜单 / 桌面快捷方式，并在「控制面板 → 程序」写入卸载项。
4. 可选：**开机自启**（默认勾选）——创建计划任务 `ZTCenter_AutoStart`，登录后以最高权限静默启动，不弹 UAC，仅在托盘显示图标。

组件页可自由勾选；安装完成后可直接启动，之后也能在「设置 → 启动与后台运行」中随时开关开机自启。

卸载：控制面板卸载，或开始菜单「卸载 ZeroTier 中文控制台」。卸载流程：

1. 先请控制台优雅退出（`--quit`，确保托盘图标被移除），再结束残留进程与官方托盘 UI，删除开机自启计划任务与 Run 项；
2. **一并卸载官方 ZeroTier One 内核**（不再单独询问，避免残留服务与驱动）；
3. 清理官方 MSI 卸载后残留的 `zerotier-cli.bat` 等包装脚本与空目录；
4. 删除本控制台数据 `%APPDATA%\ZTCenter`（标签、设置、planet/moon 备份、下载的安装包）；
5. 询问是否删除 `C://ProgramData//ZeroTier`（节点身份、planet、moons、网络配置）——**默认「是」**彻底清理；选「否」可保留节点身份，便于日后重装沿用同一节点 ID。

### 2.2 便携运行（不安装）

直接运行 `dist\ZTCenter.exe`，首次启动会请求管理员权限。此方式要求系统已装好官方 ZeroTier One。

### 2.3 运行要求

- Windows 10 / 11（x64）
- 官方服务名 `ZeroTierOneService`（合并安装包会自动安装）
- **管理员权限**：`authtoken.secret` 仅管理员可读，替换 planet、重启服务同样需要提权；程序启动时自请求提权

## 3. 快速开始

1. 安装（或直接运行 `ZTCenter.exe`），UAC 提示选择「是」。
2. 「网络管理」输入 16 位网络 ID → 加入 → 到控制器（my.zerotier.com 或自建）授权节点。
3. 「标签管理」设置中文名称、颜色、分组，仅影响本机显示。
4. 「根节点」可导入自建 planet；「管理 MOON」可添加/删除卫星根节点。
5. 关闭窗口即最小化到托盘；按 `Ctrl + Alt + Z` 随时唤出。

## 4. 关键实现说明

### 4.1 与官方服务的关系

- 复用官方 `zerotier-one_x64.exe` 服务，所有操作走官方 HTTP API（`/status`、`/network`、`/peer`），不注入、不挂钩、不修改官方文件。
- 鉴权令牌从 `C:\ProgramData\ZeroTier\One\authtoken.secret` 读取，仅在本机内存中使用，不落盘、不外发。

### 4.2 planet 替换流程

1. 读取并**校验**目标文件（类型字节、40 位世界 ID、毫秒时间戳合法性）。
2. 自动备份当前 planet 至 `%APPDATA%\ZTCenter\planet-backup\planet-before-replace-*.bin`。
3. 停止服务 → 写入 `C:\ProgramData\ZeroTier\One\planet` → 启动服务。
4. 首次运行会额外保存 `planet-initial.bin` 作为「出厂备份」，可一键还原。

> 替换后 `planet` 的世界 ID 必须与你的网络控制器世界 ID 一致，否则节点会一直离线。

### 4.3 MOON（卫星根节点）

- 文件位置：`C:\ProgramData\ZeroTier\One\moons.d\<moonid>.moon`（程序自动创建目录）。
- 添加：导入 `.moon` 文件，或粘贴十六进制 / Base64 → 校验类型字节（必须为 `2`）、40 位世界 ID、毫秒时间戳 → 写入 `moons.d` → 执行 `zerotier-one_x64.exe -q orbit <id> <id>` 立即生效（CLI 不可用时回退重启服务）。
- 删除：先 `-q deorbit <id>`，再把文件备份到 `%APPDATA%\ZTCenter\moon-backup\` 后删除。
- 状态判定：`moons.d` 中的 MOON ID 与 `/peer` 返回的 `role = MOON` 节点比对，一致显示「已生效」，否则「待生效」。

### 4.4 内核版本与升级

- 版本取自注册表卸载项 `DisplayVersion`（免管理员可读）；实时版本以 `/status` 的 `version` 为准。
- 目标版本 **1.16.2**：变更仅涉及 Windows 安装包行尾、控制器内部与网络容量上限（`ZT_MAX_NETWORK_SPECIALISTS` 256→512），并修复 Windows 下切换网络的多分钟延迟，**不影响本地 API 与 MOON/planet 机制**。
- **版本信息卡片**分四行显示：当前控制台版本 / 最新控制台版本 / 当前内核版本 / 最新内核版本。早期版本误把控制台版本（`ZeroTier 中文控制台`）当成内核版本读取——因为注册表匹配只判断了 `DisplayName` 是否以 `zerotier` 开头；v1.4.0 改为严格匹配 `ZeroTier One` 并排除含「控制台/中文/ZTCenter」的条目。
- 当前内核版本优先取运行中服务的 `/status.version`，仅在**内核已安装**时采用；未安装时统一显示「未安装」，避免用演示或残留数据误导。
- 应用内升级（设置 →「ZeroTier 内核」）提供三个入口：
  - **安装官方 1.16.2**：优先使用本地包（程序目录、`upgrade\` 子目录、`%APPDATA%\ZTCenter\downloads\`），未找到时自动下载，按钮实时显示百分比；
  - **手动选择安装包…**：自选任意官方 `.msi`（校验 OLE 复合文档头与体积），适合离线/内网环境；
  - **打开官方下载页**：浏览器打开 `download.zerotier.com`。
- v1.2.0 曾出现「点击安装无反应」：安装后 MSI 落在程序目录根部，而查找逻辑只扫 `upgrade\` 子目录，找不到包便静默转入下载、无可见进度。v1.3.0 已扩大查找范围，并把下载进度/失败原因显式反馈到界面。

### 4.5 后台隐藏（两种方式）与开机自启

隐藏方式在「设置 → 启动与后台运行 → 隐藏方式」切换，也在托盘菜单与概览「快捷操作」中提供入口：

| 方式 | 表现 | 恢复 |
| --- | --- | --- |
| 隐藏到托盘 | 窗口隐藏，托盘图标常驻，可右键菜单操作 | 点托盘图标 / `Ctrl + Alt + Z` |
| 彻底隐藏 | 窗口隐藏 **且托盘图标被移除**，只在后台运行 | `Ctrl + Alt + Z` 或重新运行 `ZTCenter.exe`（单实例 IPC 唤起） |

- 选择「彻底隐藏」后，该偏好会被记住：下次关闭窗口同样彻底隐藏，程序启动时也不创建托盘图标。
- 唤出界面时会临时补回托盘图标，方便操作；再次隐藏则重新移除。
- 恢复通道独立于托盘：全局热键与单实例 IPC 都不依赖托盘图标，因此即使图标被移除也不会「失联」。
- **边界说明**：这只是隐藏界面，不做任何反检测处理——进程在任务管理器中照常可见，日志照常写入，也不会伪装进程名。
- **官方托盘图标**：官方内核自带托盘 UI（`zerotier_desktop_ui.exe`，蓝色 Z，菜单为 "Quit ZeroTier UI"）。安装包在装完内核后立即结束该进程并清理其 Run 项；应用启动时按设置（默认开启）再执行一次，只保留本控制台图标。仅结束进程 + 清理自启项，不删除、不改名官方文件，因此不影响内核升级与修复安装。
- 开机自启走**计划任务**（`schtasks /SC ONLOGON /RL HIGHEST`），登录静默启动、不弹 UAC；失败时降级到注册表 `Run` 项。
- **优雅退出通道**：`ZTCenter.exe --quit` 通过单实例 IPC 让已运行实例自行退出（`pystray` 正常移除托盘图标），并用互斥体轮询确认进程已结束。卸载程序先调用它，再以 `taskkill` 兜底，避免「卸载后托盘图标残留」。
- 静默参数 `--silent`：不显示主窗口，按当前隐藏方式驻留后台。

### 4.7 安装包构成（NSIS）

- 脚本：`installer\ZTCenter.nsi`；编译器：`tools\nsis\makensis.exe`（NSIS 3.10）。
- 载荷：`dist\ZTCenter.exe` + `upgrade\ZeroTierOne-1.16.2.msi`，LZMA 固实压缩，单文件约 26 MB。
- 覆盖安装时**不调用 taskkill**：把正在运行的旧 exe 重命名为 `.old` 后写入新文件，并标记重启后删除，避免进程占用导致安装中断。
- 注册表统一写入 64 位视图（`SetRegView 64`），避免落进 `WOW6432Node`。
- 内核静默安装用 `msiexec /qb`；若返回码非 0/3010，会提示是否改用官方安装向导重试（驱动安装可能需要人工确认）。

### 4.8 状态指示的判定规则

左下角与头部状态由 `_compute_status()` 统一计算，优先级从高到低：

| 状态文案 | 判定条件 |
| --- | --- |
| 需要管理员 | 未提权（读不到 `authtoken.secret`） |
| 内核未安装 | `C://ProgramData//ZeroTier//One//zerotier-one_x64.exe` 不存在 |
| 服务已停止 / 服务正在启动… | Windows 服务 `ZeroTierOneService` 非运行态 |
| 服务不可访问 | 能提权但打开服务管理器失败 |
| 本地接口异常 | 服务在跑但本地 API 报错 |
| 根节点缺失 / 根节点异常 | planet 文件不存在 / 结构校验失败 |
| **官方-在线 / 官方-离线** | planet 世界 ID = `149604618`（`ZT_WORLD_ID_EARTH`），或文件内含官方根服务器地址 |
| **自定义-在线 / 自定义-离线** | 其他 planet（自建世界） |
| …`·待重启` | 磁盘上的 planet 世界 ID 与运行中服务不一致，需重启服务才生效 |

官方判定不依赖网络：`world_id == 149604618` 或 planet 文件字节中出现 `62f865ae71 / 778cde7190 / 992fcf1db7 / cae7faf58a` 任一官方根地址即视为官方，否则为自定义。

### 4.9 网络列表的字段解析（曾导致列表只剩标题行）

ZeroTier 本地 API 的 `/network` 返回 `"assignedAddresses": ["10.60.222.248/24", "fd00::1/64"]`——**字符串数组**。早期代码按 `{"address": ...}` 对象取值，在真实环境下抛 `AttributeError`，异常被上层 `try/except` 吞掉，表现为「每行只剩名称和状态、详情按钮也消失」。

- 新增 `core.ztapi.net_addresses/net_ipv4/net_ipv6/net_dns_servers/net_routes/net_flags`，同时兼容字符串数组与对象数组；
- 演示数据改为与真实 API 完全一致的形状，避免同类问题再被演示数据掩盖；
- 列表渲染改为**逐行 try/except**：单行异常只影响该行并标红提示，同时写入 `%APPDATA%\ZTCenter\ztcenter.log`。

### 4.10 对端信息与 P2P/中继判定

`/peer` 的返回里没有「对端名称」，也没有「对端在其网络中的虚拟 IP」。本项目的处理方式：

| 展示项 | 来源 | 说明 |
| --- | --- | --- |
| 名称 | 本地标签 | 协议不提供节点名，用本地标签显示（如「家里的 NAS」）；未标注时显示 10 位地址 |
| 角色名 | `role` | `PLANET` → 根节点、`MOON` → 卫星节点、`LEAF` → 成员节点 |
| 公网地址 | `paths[].address` | 取 `active && preferred` 的首条路径 |
| P2P / 中继 | `tunneled` + `active` 路径 | `tunneled=true` 为中继；无活跃直连路径也视为中继 |
| 虚拟 IP | 本机 ARP / 邻居表 | ZeroTier 网卡 MAC 末 5 字节 = 节点地址，据此把 MAC 反查成 IP；仅在最近有过二层通信时存在，否则显示「ARP 表暂无记录」 |
| 延迟 | `latency` | 毫秒；0 或缺失表示内核「尚未测量」（常见于旧版本节点）。此时程序会**自动用本机 ping 探测一次**，显示为「约 9 ms」（明确标注是探测值），探测不到则保留「未测量」 |

本机联机方式（`P2P` / `中继` / `P2P/中继`）只统计**成员节点**并排除本机记录，结果同时出现在右上角与左下角状态中。

### 4.11 网络列表排序（拖拽 + 记忆）

- 交互与对端列表一致：拖动每行左侧的 `≡` 手柄即可调整顺序，松手立即保存（`%APPDATA%\ZTCenter\net_order.json`）并提示「网络显示顺序已保存」。
- 默认顺序为内核 `/network` 返回顺序（近似「加入顺序」）；新加入的网络追加在末尾，不会打乱已排好的顺序。
- 仅有 1 个网络时手柄为灰色且不绑定拖拽事件，避免误操作。
- 顺序只影响显示，不影响 ZeroTier 行为；搜索过滤后仍保持该相对顺序。

### 4.12 对端列表排序（置顶 + 拖拽 + 记忆）

顺序由 `core/peer_order.py` 决定，规则按优先级：

1. **根节点（PLANET / MOON）固定置顶**，顺序取内核 `/peer` 返回顺序，不可拖动；
2. **成员节点**按用户拖拽后的顺序排列；未出现在已保存顺序里的新对端追加在已有成员之后（因此默认顺序就是内核返回顺序，近似「加入顺序」）；
3. **本机固定在最后**作为参照，不可拖动。

- 交互：成员行左侧的 `≡` 手柄按住拖动，行会实时让位；松手即写入 `%APPDATA%\ZTCenter\peer_order.json` 并提示「顺序已保存」。
- 拖拽边界：不能把成员拖到根节点之上或本机之下（`_member_range()` 夹取索引）。
- 只保存成员地址；根节点与本机不参与持久化，网络变化后自动重排。
- 该顺序只影响显示，不影响 ZeroTier 行为。

### 4.13 服务控制与管理员权限

- 服务控制走 `advapi32`（`OpenSCManagerW / OpenServiceW / QueryServiceStatus / ControlService / StartServiceW`），不依赖 `sc.exe`。
这里修过两个独立缺陷，都曾被误报成「需要管理员权限」：

| 版本 | 缺陷 | 现象 |
| --- | --- | --- |
| v1.8.0 | `OpenSCManagerW / OpenServiceW` 等未声明 `restype`，ctypes 默认 `c_int`，64 位下 `SC_HANDLE` 被截断 | `ERROR_INVALID_HANDLE(6)`；服务状态恒显示「未知」 |
| v1.9.0 | `ControlService` 第二个参数是**控制码**（`SERVICE_CONTROL_STOP = 1`），却传了访问权限码 `SERVICE_STOP = 0x20` | SCM 判定「服务不接受此控件」→ `ERROR_ACCESS_DENIED(5)`，**即使已经是管理员** |

- 现已声明全部 `argtypes/restype`，并区分控制码与访问权限码；错误文案按码解释：`5 拒绝访问 / 6 句柄无效 / 1060 服务不存在 / 1072 标记删除 / 1056 已在运行`。
- 该缺陷同时影响「替换 planet」（同样需要停/启服务），v1.9.0 一并修复。
- 未提权时点击「重启 ZeroTier 服务」不再直接报错，而是提示并以管理员身份重新启动自身（安装包 exe 已嵌入 `requireAdministrator`，开机自启走 `HIGHEST` 计划任务，三处入口都保证高权限）。

### 4.14 对端标签（本地）

- 存储：`%APPDATA%\ZTCenter\peer_labels.json`，以 10 位对端地址为键，字段 `label / color / group / note`。
- 入口：对端列表每行的「标签」按钮；保存后立即刷新，列表按「本机 → 已标注（按分组）→ 未标注成员 → 未标注根节点」排序。
- 标签只在本机生效，不写入网络配置、不同步给对端，也不上传（卸载时可选择一并删除）。
- 与网络标签（`labels.json`）互相独立，互不影响。

### 4.15 界面缩放与对话框布局

- `ui/scaling.py` 统一处理缩放。注意 customtkinter 的 `set_*_scaling` 是**在系统 DPI 基础上乘算**的（1.5 × 1.5 = 2.25），因此传入的是相对系数 `目标倍数 / 系统倍数`，实际生效倍数才等于所选值。
- 窗口尺寸由 `_fit_window()` 按「逻辑尺寸 × 实际倍数」计算并居中，100%~200% 均不会超出屏幕（已按 1.0 / 1.5 / 2.0 实测）。
- 修改缩放会重建界面并立即生效，无需重启。
- **修复**：对话框（确认框等）此前把内容区 `pack(expand=True)` 放在按钮区之前，窗口偏小时按钮区被压成 0 高度——即「点立即隐藏只有提示、没有确定按钮」。现在按钮区先按底部固定，内容区再占用剩余空间，并按文本行数自适应窗高。

## 6. 常见问题

**Q：装完还要再装官方客户端吗？**
不需要。合并安装包已包含官方内核（服务 + 驱动）。便携版 `ZTCenter.exe` 则要求系统已装官方 ZeroTier One。

**Q：安装时提示内核静默安装失败？**
多为网卡驱动需要人工确认。按提示选择「重试」会拉起官方安装向导，勾选安装驱动即可；也可稍后手动运行 `C:\Program Files\ZTCenter\ZeroTierOne-1.16.2.msi`。

**Q：状态一直是「等待授权」？**
加入网络后需在控制器勾选授权（Auth）；私有网络必须授权才会分配地址。

**Q：提示「读取 ZeroTier 鉴权文件被拒绝」？**
以管理员身份运行；计划任务自启需具备「最高权限」。

**Q：替换 planet 后所有网络离线？**
planet 与控制器世界不匹配。到「根节点 → planet 备份」恢复出厂备份或替换前备份，服务会自动重启。

**Q：MOON 显示「待生效」？**
MOON 服务器未启动 / UDP 不通，或文件已写入但 `orbit` 未成功（需管理员）。可「重启服务」后刷新。

**Q：重启服务提示「拒绝访问（错误码 5）」？**
v1.9.0 已修复（控制码传错所致，见 4.13）。若仍是 5，请确认客户端确实是以管理员身份运行（设置页底部与「节点信息」会显示当前权限）。

**Q：重启服务提示「无法打开 ZeroTier 服务」？**
v1.8.0 已修复（见 4.13，句柄被截断导致，与权限无关）。若仍失败，检查服务是否存在：`sc query ZeroTierOneService`；提示「服务不存在」说明内核未安装或服务名被改过。

**Q：对端延迟显示「未测量」或「约 xx ms」？**
`未测量`：内核还没测（旧版本节点如 v1.12.x 不上报）。此时程序会自动 ping 该对端公网地址补一个参考值，成功则显示 `约 9 ms` 并带提示说明；若对端禁 ICMP 或仅内网可达，则仍是「未测量」，与本机实际通信后内核会自行给出准确值。

**Q：点「安装官方内核」没反应？**
v1.3.0 已修复查找逻辑并显示下载进度。若仍无反应，用「手动选择安装包…」直接指定本地 `.msi`，或「打开官方下载页」手动下载后再选择。

**Q：左下角显示「自定义-离线」是什么意思？**
当前使用自建 planet 且节点未连上任何根节点。请检查 planet 世界 ID 是否与控制器一致、自建根节点端口是否可达。显示「官方-在线/离线」表示 planet 世界 ID 为官方地球世界 `149604618`。

**Q：点「立即隐藏」只看到提示、没有按钮？**
v1.6.0 已修复（见 4.15，按钮区被内容区挤压）。若仍出现，请确认版本号 ≥ 1.6.0。

**Q：界面缩放怎么调？**
设置 →「外观与刷新 → 界面缩放」。默认「跟随系统」按 Windows 显示设置自动适配；也可强制 100%~200%，立即生效。

**Q：对端标签会同步给别人吗？**
不会。标签只存本机 `%APPDATA%\ZTCenter\peer_labels.json`，不写入网络配置、不上传。换机器需自行迁移该文件。

**Q：对端详情里的「虚拟 IP」显示 ARP 表暂无记录？**
该值由本机 ARP 表反查，只有在与该对端发生过二层通信后才会有记录。与对端 ping 一下或访问其服务后再打开即可看到。

**Q：根节点能不能拖到下面？**
不能。根节点固定置顶（需求约定），只有成员节点可拖动排序，且拖拽范围被限制在根节点之后、本机之前。

**Q：网络列表的顺序也会记住吗？**
会，存 `%APPDATA%\ZTCenter\net_order.json`，与对端顺序（`peer_order.json`）分开保存，互不影响。

**Q：自定义顺序会不会因为重启丢失？**
不会，存在 `%APPDATA%\ZTCenter\peer_order.json`。卸载时随 `%APPDATA%\ZTCenter` 一并清理。

**Q：在线对端数量包含本机吗？**
不包含。统计与联机方式判定都会排除本机记录。

**Q：网络列表里看不到 IP / 详情按钮？**
v1.5.0 已修复（见 4.9）。若仍异常，打开 `%APPDATA%\ZTCenter\ztcenter.log` 看是否有「渲染网络 xxx 失败」记录，并把该行内容发我。

**Q：右键菜单里「快速切换网络选项」是做什么的？**
直接切换该网络的 4 个开关：允许托管配置、允许全局 IP、允许默认路由（全部流量走此网络）、使用网络 DNS。等同于详情页里的同名开关，改完立即写入内核配置。

**Q：为什么「当前内核版本」显示未安装，但服务在跑？**
版本以注册表卸载项 + 内核可执行文件双重判定。若内核文件存在而注册表项缺失（例如被手动删除），会显示「未知」，此时用「手动选择安装包…」做一次修复安装即可。

**Q：卸载后托盘图标还在？**
v1.4.0 卸载程序会先发 `--quit` 让程序自己退出并移除图标。若仍残留，多为 Explorer 的图标缓存未刷新——鼠标划过或重启资源管理器即消失。

**Q：升级内核后版本号没变？**
版本号在启动时读取，需退出并重新打开控制台。

**Q：开机自启后没看到窗口？**
预期行为（`--silent` 不显示主窗口）。按当前隐藏方式驻留：托盘模式点图标，彻底隐藏模式按 `Ctrl + Alt + Z`。

**Q：彻底隐藏后托盘图标没了，怎么找回界面？**
按 `Ctrl + Alt + Z`，或再次双击 `ZTCenter.exe`（不会启动第二个实例，只会唤起已有窗口）。之后到设置里把「隐藏方式」切回「隐藏到托盘」即可。

**Q：托盘图标被折叠进「隐藏的图标」？**
任务栏设置中设为「始终显示」。

## 7. 安全与合规

- 仅与本机 `127.0.0.1` 的 ZeroTier 服务通信，不连接任何第三方服务器。
- 不收集、不上传节点信息、网络 ID、标签数据。
- planet 替换属高级操作，请使用自有/可信的世界配置；公共网络环境中请遵守所在组织与当地法规。

## 8. 已知限制

- 仅支持 Windows x64；服务控制依赖 `ZeroTierOneService` 名称（官方安装包默认）。
- 不支持内置网络控制器（controller）的创建与管理，需另行部署。
- planet / moon 文件校验基于公开的 World 序列化结构（类型 1 字节 + 世界 ID 8 字节 + 时间戳 8 字节），自定义魔改格式会被拒绝。
- 安装包未做数字签名，首次运行可能触发 SmartScreen 提示（「更多信息 → 仍要运行」）。
